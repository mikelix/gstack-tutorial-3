# 选择你的翻译服务——请在进入第 2 阶段前阅读

**本页为什么存在。** 本教程早期草稿只是告诉你"使用 `--translator llm`，
绝不回退到 Bing 或 Google"。那其实只是把作者自己的配置当成规则往下传。
你不能盲目照搬这条规则，因为**实际上哪些翻译服务对你可用，取决于你的
电脑、你的网络、你所在的国家，以及你是否持有付费 API 密钥**——而这些
条件对每一位读到本文的研究生来说都不一样。

本页帮你做这个决定。它还记录了一种在实测这些选项时发现的失效模式，
而早期版本的关卡链是无法抓到它的。

---

## 1. 三个选项，按工具实际呈现的样子

`videocaptioner subtitle --translator {llm,bing,google}`

| 选项 | 费用 | 需要 API 密钥 | 英译中质量 |
|---|---|---|---|
| `llm` | 付费（按 token 计费） | **需要** | 最好——有上下文感知，能处理习语与语域 |
| `bing` | 免费 | 不需要 | 机械直译，逐段处理 |
| `google` | 免费 | 不需要 | 机械直译，逐段处理 |

### 默认值并不是本教程假设的那个

```
--translator {llm,bing,google}
        Translation service (default: bing)
```

**`--translator` 的默认值是 `bing`，不是 `llm`。** 如果你省略该参数，
你会悄无声息地用上 Bing。正因如此，本教程每一条命令都显式写出翻译服务。
不要为了少打字而省略这个参数。

### 第二个陷阱：`optimize` 与 `split` 同样是 LLM 步骤

`videocaptioner subtitle` 最多会运行三个步骤：**Split**（按语义边界
重新分段）、**Optimize**（修正 ASR 错误与标点）、**Translate**（翻译）。
前两步*无论你选哪个翻译服务*都由 LLM 驱动。所以"我用免费的 Bing 翻译器"
并不等于"我完全不需要 API 密钥"——你还需要加上 `--no-optimize
--no-split`，或者为这两步准备一个 LLM 密钥。请提前想清楚这一点，
不要等运行到一半才发现。

## 2. 我们实测免费选项时观察到的结果

实测于 2026-09-15，Windows 11，来自香港网络，`videocaptioner` 1.4.2。
**你的结果可能不同——这正是本页存在的意义。** 请自行重跑第 4 节的检查，
而不是直接相信下面这张表。

| 翻译服务 | 我们实测的结果 | 说明 |
|---|---|---|
| `bing` | **直接失败** | `Failed to init Bing session: 404 Client Error: Not Found for url: https://edge.microsoft.com/translate/auth`——上游认证端点已变更或被下线。退出码 5。至少这个失败是吵闹的。 |
| `google` | **静默产出未翻译的英文** | 触发 `429 Too Many Requests`，记录了错误，然后把原始英文当作"译文"输出，并**以 0 退出**，附带 `✓ Done -> file.srt (2 segments)`。 |
| `llm`（DeepSeek） | 可用 | 在 32 段和 1086 段的片子上都流畅、自然。 |

### `google` 的结果才是关键

再读一遍那一行。命令**报告了成功**。分段数正确。输出文件存在且格式良好。
它唯一的问题是：里面没有中文。

一个信任 `✓ Done` 的学生会把英文字幕烧进视频并直接发布。而最初设计的
关卡链**根本抓不住这个问题**：

- Gate T2（翻译服务溯源）——通过。实际运行的确实是 `google`。
- Gate T3（分段一致性）——通过。源文件与目标文件都是 2 段。
- Gate T4（合成保真度）——通过。视频本身没问题，只是画面上的文字错了。

这就是为什么现在有了 **Gate T3b**（`starter/scripts/run_gates.py`）：
它检查目标文件是否真的包含汉字，以及是否有任何一段与源文本逐字相同。
它是**因为**这次发现才被加上的，而不是事先预判到的。详见
`reviews/04-qa-report.md`。

> **可迁移到本工具之外的通用教训：** 一个静默降级的免费服务，比一个
> 吵闹失败的服务更危险。Bing 的 404 只浪费你一个下午；Google 的
> 「429 然后透传」可能毁掉你的一次提交。

## 3. 决策指南

按顺序往下看，在第一条描述你情况的地方停下。

| 如果你…… | 使用 | 原因 |
|---|---|---|
| 已有（或能申请到）任意 OpenAI 兼容服务商的 API 密钥 | **`llm`** | 英译中质量遥遥领先，而且失败时是吵闹的而非静默的。本教程试点运行用的就是这个。 |
| 身处中国大陆，或在严格防火墙之后 | **`llm`，搭配境内可达的服务商**（DeepSeek、Moonshot、智谱、通义千问——均兼容 OpenAI 接口） | Google 与 Bing 的端点经常不可达；境内 LLM 端点通常可达。本教程固定使用的就是 DeepSeek。 |
| 完全没有预算，也拿不到任何密钥 | `google` 或 `bing`，**外加 `--no-optimize --no-split`**，**外加强制启用 Gate T3b** | 免费，但请见第 2 节——务必在信任输出之前先确认它真的包含中文。免费翻译服务绝不可跳过 T3b。 |
| 拥有院校的 OpenAI 或 Azure 配额账号 | **`llm`**，指向该端点 | 已经付过费了。用 `--api-base` 指向你所在机构的网关。 |
| 只是在一段 30 秒的片子上冒烟测试流水线的机械流程 | `google` 可以接受 | 此时质量不重要，你在测试的是管道本身。产出正式结果前请切换到 `llm`。 |

### 费用：让付费选项成为一个真实的选择，而不是一个模糊的顾虑

试点的 41 分钟片子有 1086 段。按 DeepSeek 的定价，这只是几美分——翻译
一小时语音的成本比一杯咖啡还便宜。**对大多数学生来说，真正的障碍是
拿到密钥和支付方式，而不是单次运行的费用。** 请据此分配你的精力：
搭建是难点，使用很便宜。

## 4. 在进入第 2 阶段之前先验证你自己的访问条件（不要跳过）

在一个可丢弃的小文件上做这件事，而不是在 41 分钟的片子上才发现问题。
创建 `probe.srt`：

```
1
00:00:00,000 --> 00:00:02,000
hello this is a short test

2
00:00:02,000 --> 00:00:04,000
of the translation pipeline
```

然后尝试你打算使用的翻译服务：

```bash
videocaptioner subtitle probe.srt --translator llm \
    --target-language zh-Hans --layout target-only -o probe_out.srt
```

**现在真的打开 `probe_out.srt` 看一眼。** 三种结果：

1. **中文文本** → 你的翻译服务可用。把它记入
   `starter/versions.lock`，然后继续。
2. **一个明确的错误**（非零退出码、报错堆栈、404）→ 该翻译服务对你
   不可用。试试第 3 节表格的下一行。
3. **英文文本，附带 `✓ Done`** → 静默透传。这个翻译服务*并没有*正常
   工作，尽管它声称成功。不要继续；换一个。

结果 3 是最容易让人损失一整天的那种。请亲自打开文件看一看。

---

## 5. 记录你的决定

无论你选了哪一个，都请把它写进 `starter/versions.lock`
（从 `versions.lock.template` 复制而来），如果使用的是 `llm`，还要
记下 `api_base` 与 `model`。原因有两个：Gate T2 会检查它，而且未来
阅读你工作成果的人（包括未来的你自己）需要知道是什么产出了这段译文。
LLM 服务商即便在模型名称不变的情况下，也会随时间改变模型行为，
这也是模板中还要求填写运行日期的原因。
